## Auth & middleware
- NextAuth `signIn` page is `/login` (`src/auth.ts:8`).
- Middleware protects (unauth → `/login?callback-url=…`):
  `/cart`, `/profile`, `/wishlist`, `/updatepassword`, `/UpdateuserData`, `/chekout`, `/allorders`, `/addresses`, `/addadress`, `/orderdetails`.
- Middleware redirects authed users away from:

## Auth token extraction — two patterns

**Server Actions** (`_servecies/`): Read the NextAuth session cookie manually, decode JWT via `next-auth/jwt`'s `decode()`, extract `token.token` and pass as `token` header.
See canonical example: `_servecies/cart/add_to_cart.ts`.

**Route Handlers** (`api/`): Use `getToken({req})` from `next-auth/jwt` to get the token from the request, then pass `token.token` in the `token` header.
See: `api/cart/route.ts`, `api/addToWishlist/route.ts`.

Both patterns send the external API token as a `token` header (not `Authorization: Bearer`). The external API key is stored in `token.token` on the JWT.

## Providers
Root layout wraps: `<Providers>` (React Query) → `<NextAuthProvidor>` (NextAuth SessionProvider) → `<Nav/>` → `{children}` → `<Toaster/>` → `<Fotter/>`.
Add new client-side context providers inside the existing tree in `src/app/layout.tsx`.

- `Providers` uses `@tanstack/react-query` with `staleTime: 60 * 1000`, singleton QueryClient per browser session.
- `NextAuthProvidor` is a thin `'use client'` wrapper around `SessionProvider`.

## Data fetching pattern
- Server Components for reads where possible; pass data down.
- Client interactivity (sliders, forms, dialogs) uses `'use client'`.
- **Dual mutation pattern:**
  - **Server Actions** (`_servecies/`): Server-side mutations that pull the bearer token from the NextAuth cookie and call the external API.
  - **Route Handlers** (`api/`): Client-side calls `fetch('/api/...')` → handler calls external API with `getToken()`.
  Both exist for cart, wishlist, etc. Match the pattern used by neighboring code.
- Client-side caching/fetches use TanStack Query via the `Providers` wrapper.
- `next/fetch` revalidation: `next: { revalidate: 3600 }` used in Server Components (see `page.tsx:92`).
